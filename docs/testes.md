# Tests: file format and cards

Read only when writing, changing or reading manual tests.

- `TESTES-PENDENTES.md` is the source of the GitHub cards and is also opened by the user through the link in the reply (19/11/2026), **in Portuguese**: compact, no instructions or result lines. Format: "## section", "> antes de testar" (optional, one line), "### Tnn – título (vX.Y.Z)" (+ " (Crítico)"), "F: o que fazer" and "E: o que deve acontecer" (one line each; summarized, only what the user and non-IT colleagues need: where to click and what should appear); question: "### Pn – título" and "?: pergunta". A test that depends on a file outside git: say in "> antes" that it is on the development computer.
- **GitHub cards** (`.github/workflows/testes.yml`): on each merge into master, every new test or question becomes a card (issue, label "teste") with the full text and the "✅ Passou" and "❌ Falhou" boxes; cards of tests that leave the file close by themselves. `/testes` reads the cards with `node .github/scripts/ler-resultados.js` and deletes the resolved ones with `node .github/scripts/apagar-testes.js T03 T05` (do not read the whole file or cards).
- **Every test gets a card** (18/11/2026, user): a card belongs to a test by number **and** title. A test with a number already used by another test (e.g. the colleague's pull request merged while the owner has tests not in master yet) still gets its card, marked "número repetido", and the "Cartões de teste" run turns red. Fix: renumber the **newer** test, the one without comments, to the next free number; never delete a test because its number repeats (only a truly repeated test, same content, is deleted). Owner: after updating the branch with master, run `npm test` (it refuses repeated numbers) and renumber your own tests that are not in master yet. Never change the title of a test that already has a card. Cards closed by hand: `/testes` reads them too.
- An uncommented test = it worked. Never delete a test without "Passou" on the card (or the user's request). Only append at the end and check that the count did not go down.
- Improvement with several stages: each stage's tests go into the file, but the user tests everything together at the end. Only stop earlier for a **critical** test (writes to an official system – SEI, spreadsheet – or decides the direction of the next stage), marked "(Crítico)". Automated tests run at every stage.
- Minimum check: `npm test` and `npm run conferir`. **Never test with screenshots** (nor open the browser to see the screen) without the user's explicit request.
