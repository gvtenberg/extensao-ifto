# IFTO SEI: editor

**Sections**: Tables in the editor (v0.24.0) · Long numbers in edital items (v0.25.0) · MINUTA mark in editais (v0.22.0) · Automatic save in the editor (v0.31.0) · Hidden boxes and typed numbers (v0.37.0) · AGU formatting (v0.38.0)

## Tables in the editor (v0.24.0)

- Every unit, every document type; one switch for each part in the settings (`moverTabelas`, `margensTabela`, on by default).
- Cut/copy and paste in the **same editor window**: when the copied part has a table, the paste puts back the editor's own copy (model), not the clipboard HTML, so width, column widths and margins stay. Ctrl+Shift+V, drag and drop, pasting in another window and parts without a table stay with the SEI. Ctrl+Z undoes it.
- SEI 5 keeps the left margin of a table in its own `recuo` setting (only with the table aligned to the left) and the other margins in the HTML styles; saved as `margin:10px auto 10px 28px` like the old SEI. v0.25.1: "Propriedades da tabela" has four fields in px (Acima, Direita, Abaixo, Esquerda) filled with what the editor shows now (Direita: the saved value, else 0); on OK only the changed fields apply; pasting the old `margin:` format in a field fills all four. A 4th button in "Alinhamento" ("Alinhar com o texto") aligns left and fills 10, 0, 10, 28 px (text styles use margin-left .75cm). Button text inside CKEditor buttons only shows with `ck-button_with-text` (why the v0.24.0 button looked blank).
- SEI 5 bug: the "estilo" command runs `removerFormatacaoAprimorado` (`keepFormatting: true`) on each paragraph, and when the paragraph is alone in a cell it also removes the cell attributes (`tableCellBackgroundColor`, borders, padding, sizes, `htmlTdAttributes`). v0.25.3 (with the "Margens da tabela" setting): the extension saves the cell attributes before that command and puts them back right after, in the same change (one Ctrl+Z). The "Remover formatação" button (no `keepFormatting`) still clears everything.

## Long numbers in edital items (v0.25.0)

- "Item nível 2/3/4 Edital" put the number in a fixed box (10, 15, 18 mm); "10.10." does not fit and the text goes to the next line (editor, document, PDF). Swapping to "Item_Nivel2" is not possible everywhere: in Minuta 3384558 the SEI does not allow it in the main section (`permitidoEm`).
- Fix (user's choice, 18/11/2026): a `<style>` block at the start of the first edital item, like SEI Pro's MINUTA mark (the SEI keeps and prints it). It only lets the box grow (`min-width` = old width, `box-sizing:border-box`), so short numbers stay identical. Recognized by the comment `extensao-ifto: numeracao do edital` (the editor drops the `<style>` attributes). "Remover marca MINUTA" does not touch it.
- The box "Corrigir a numeração" appears in every unit and document type only when a paragraph is really broken (first letter below the first line), checked again 1.5 s after each change; nothing changes without the click; never saves.

## MINUTA mark in editais (v0.22.0)

- The "MINUTA" in the background is not a paragraph: SEI Pro puts a `<style>` block in the text (`data-style="seipro-watermark"`, `content: "MINUTA"`) plus a label `span.minutaAncora` "* MINUTA DE DOCUMENTO" (one pair per marked paragraph). Creating the Edital from the minuta copies them. In SEI 5, deleting the label is not enough: the style block stays hidden in the paragraph and keeps printing MINUTA (v2 of Edital 3390039, 18/11/2026), and editing the HTML by hand is not saved.
- In the editor window (`acao=editor_montar`), only for type **Edital** (window title "SEI/IFTO - número - Edital …"; "Minuta de Edital" keeps the mark), a box "Remover marca MINUTA" appears when the mark is in the text. It removes every style block that writes MINUTA and every label, also recognized by the text "* MINUTA DE DOCUMENTO" (v0.22.1: the SEI 5 editor gives the text without the `minutaAncora` class); a paragraph left empty is removed. Other styles and the visible word "minuta" (e.g. title "minuta de EDITAL") stay; a warning lists where it is, for the person to fix by hand.
- The extension never saves here: the person checks and clicks Salvar (closing without saving undoes it; Ctrl+Z also works in SEI 5).
- Setting "minutaEdital": Automática = only in the Direção-geral (PAL/REI/IFTO), Sempre ligada, Desligada. The editor window does not show the unit: it comes from `infra_unidade_atual` in the address (number → name saved by every SEI page) or from the SEI window that opened the editor.

## Automatic save in the editor (v0.31.0)
- "Salvamento automático" (user 19/11/2026: it is an automatic save on this computer, not a copy; it never saves in the SEI). Switches `salvamentoAutomatico` and `copiarColarConteudo`, both off by default (spec `specs/feitas/copia-editor-sei.md`, D5). Only in the editor window; the copy never leaves the computer (extension storage, no `unlimitedStorage`).
- Copy = what the SEI sends on Salvar: `infraEditor.editor.getFullData()` of the editable roots (not `somenteLeitura`) + `plugins.get('Comentario').getData().itens`; keeps all formatting, tables (margins live in the table attributes), images and links. Key `salvamentoAutomatico:<id_documento>`, overwritten every 30 s only when something changed, and right when Salvar is clicked; index `salvamentoAutomaticoIndice`.
- Save confirmed = the SEI document version (`_versaoDocumento` of the save plugin, starts as `sei.versao`) changed after the `salvar` event: the copy is deleted. Not confirmed: deleted 7 days after its last change; no space: oldest copies of other documents go first.
- Reopening: copy equal to the editor is deleted silently; otherwise box Restaurar / Ver diferenças / Descartar and the automatic copy stops until the choice (the indicator reopens the box). Copy version different from the SEI version = saved after the copy: red warning and confirmation. "Ver diferenças" (v0.31.3) is a side panel on the left (below the editor buttons, away from the extension box on the right), with no dark background: the page keeps scrolling. Indicator next to Salvar: short text, full text on mouse over.
- Restoring (and Colar): destroy + `infraEditor.montar({initialData, infra:{comentario:{itens}}})` (the 3384558 recovery method); then the extension's table, long-number and ★ style helpers start again; what they had already put in the text (style blocks for edital numbering and spacing between parts, ★ classes, table margins) is part of the saved HTML and comes back; the result is compared with the copy; if different, the stored copy is kept ("protegida") until the SEI saves. Desfazer reloads the text read just before. Never saves. v0.31.3: the SEI moves each editor's toolbar into `.infra-editor__toolbar` and `destroy` does not take it out, so the old toolbar elements are removed after destroy; the Salvar plugin only turns on after a change (`documentVersion` ≠ `lastSaveDocumentVersion`), so after mounting it sets `documentVersion = lastSaveDocumentVersion + 1`.
- Same document in two windows: the window that opened first keeps the copy (signal every 30 s, `salvamentoAutomaticoJanela:<id>`, 70 s); the other shows a warning.
- "Copiar conteúdo" keeps one manual copy (`copiaManual`); "Colar conteúdo" works only in the same document, asks for confirmation, has Desfazer.

## Hidden boxes and typed numbers (v0.37.0)
- Spec `specs/feitas/numeracao-caixas-ocultas.md`. Same setting as the long numbers (`numeracaoEdital`, "Numeração dos itens"), every unit and type. Code: `comum/numeracao-digitada.js` (pure rules, Node tests), `sites/sei/editor-caixas.js` (MAIN world, CKEditor model), `sites/sei/numeracao-caixas.js` (notices), `sites/sei/painel-revisao.js` (shared review panel).
- **Cause (Minuta de Ata 3399532, old SEI model):** part of the text sits in plain `<div>` boxes (model `htmlDiv`, no attributes). CSS Lists 3 rule: an element inherits the counters of its previous sibling only for names it does not already get from its parent. Inside a box, the title's new `item-n2` (counter-reset) is not passed to the next item, which keeps counting from outside (2.2 → "3.3"). Paragraphs side by side (no box) count right.
- Box that disturbs = `htmlDiv` with no attributes and a numbered style inside (`Item_*`, `IFTO_Item_*`). The SEI's `div style="counter-reset…"` and the "Processo/Interessado/Assunto" box have attributes and stay. "Tirar o texto das caixas" unwraps them in the model (one change, one Ctrl+Z; comments and markers stay), only in editable parts and only where the schema accepts the children.
- **Typed numbers:** a paragraph in a non-numbered style, outside tables, starting with `N.N`, `N.N.N` or `N.N.N.N` (final dot optional, then spaces/`&nbsp;`; objects such as a style block before it are skipped) can become Item_Nivel2/3/4 (user's choice of family, 26/11/2026). Paragraphs already in the Edital family stay. Style not allowed in that part (`EstiloEditing.estilos[nome].permitidoEm`): Edital family; neither: listed but not convertible.
- "Revisar e converter" opens the left review panel (only on click: extension windows never open by themselves) with each paragraph, its new style and the number it will show (counters simulated per editable part, orange when it changes: 3399532 jumps from 3.2 to 4.2 because 4.1 was deleted). Clicking a line scrolls to it and draws an outline over it for 2.5 s (outside the editor text). "Converter os marcados" also takes the text out of the boxes, removes the typed number and the spaces after it, sets the style (one change). Never saves.

## AGU formatting (v0.38.0)
- Spec `specs/feitas/remover-formatacao-agu.md`. Setting `formatacaoAgu` ("Licitação (CCL)"): Automática = only in the CCL (`sei.UNIDADE_CCL`, unit from `infra_unidade_atual`), Sempre ligada, Desligada. Any document type. Code: `comum/formatacao-agu.js` (pure rules, Node tests), `sites/sei/editor-agu.js` (MAIN world, CKEditor model), `sites/sei/formatacao-agu.js` (notice), shared `painel-revisao.js`; `editor-caixas.js` shares `raizesEditaveis`, `textoDoParagrafo` and `destacar`.
- **What it finds** (editable parts only), in the SEI model: struck text = `strikethrough` attribute (the editor turns `<s>`, `<strike>`, `<del>` and `line-through` into it); colors = `fontColor`; highlights = `fontBackgroundColor` or GHS `htmlMark`; Word comment links = `linkHref` `#_msocom_N`; "Justificativa Modificação Item(ns)" = a block whose whole text is that (accents, capitals, spaces, a final `.`/`:` ignored); balloons = markers `comentario:<id>`.
- **Removal** (one model change, one Ctrl+Z, only what stays ticked): struck runs out with the space rule (D3: one space added when two words would join, unless next to a space, opening bracket or punctuation; two spaces become one); a block left without text after its struck parts goes (D4; blocks that were already empty stay); "Justificativa…" blocks go; `fontColor` removed from all text except links; **white text** (D9, user 26/11/2026: e.g. a typed "1." hidden in white in Contrato 3399534) is deleted, except in a table cell with a background or on a colored background (it is visible there; it stays white); highlights removed (table cell shading and title style bands are classes/cell attributes: they stay); Word links unlinked, their text removed when it is only spaces or a "[A1]" tag.
- **Balloons** (D6 b, D7 checked on 26/11/2026): the SEI has no separate delete address; `Comentario.getData()` sends the list with `editor_salvar_conteudo`, so balloons leave the SEI only on Salvar (no extra warning). Deleted with the SEI's own command `removerComentario` ({id}), only when the comment has the `remove` capability (the person can edit it); others are shown greyed out. Documents made from another one as model ("Documento Modelo") come without balloons (`infra.comentario.itens` empty, TR 3399829), only the "Justificativa…" text.
- The review list is checked again on the click: if the text changed after the list opened (same id, other text or paragraph), nothing changes and the person reopens the list.
- Local check (not in git): `node ferramentas-de-teste/agu/comparar.js` applies the rules to the 4 `*-formatacao-agu.html` samples and compares each paragraph with `*-final.html` (26/11/2026: Edital 458 of 468 equal, the rest are hand edits such as dates and punctuation).
