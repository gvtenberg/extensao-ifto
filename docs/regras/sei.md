# IFTO SEI

- IFTO SEI version: it was old (before 11/2026); it is now **SEI 5.0.4** (see below). Every feature must work on the version used at IFTO.
- Initial goal: something simple, like SEI++ (https://github.com/jonatasrs/sei), which worked well for the campus up to around version 6 and lost useful features in newer versions, until it stopped working on the IFTO SEI. Colleagues currently use SEI Pro.
- (v0.1.0; v0.2.0) The extension acts only on the IFTO SEI, `sei.ifto.edu.br` (pages `controlador.php?acao=…` and `login.php`); up to v0.1.3 it was any `*.ifto.edu.br`. Exception (v0.13.0): the SICAF search also opens Compras.gov.br pages, only with the optional permission (`sicaf.md`). It saves the version and address of the last SEI opened; the icon window shows the version and when it was opened (v0.4.1).
- (v0.1.0 to v0.5.0) "Novo documento" button always visible: **removed in v0.6.0**, because SEI 5 always shows Incluir Documento.
- (v0.6.0) External document page: new = `acao=documento_receber`, existing (with or without file) = `acao=documento_alterar_recebido`. Fields: `#selSerie` (type, `onchange=trocarSerie()`), `#txtDataElaboracao`, `#optNato`/`#optDigitalizado`, `#optPublico`/`#optRestrito`/`#optSigiloso`, Salvar `#btnSalvar` (`confirmarDados()`, which first asks the SEI about a duplicate: same type, date and number). Gerar Documento page: "Externo" is `a[onclick="escolher(-1)"]`.
- (v0.8.0) Process tree (`ifrArvore` script): `Nos[n] = new infraArvoreNo("DOCUMENTO", id, pai, link, alvo, rótulo, dica, ícone, …)`; file attached = `Nos[n].src` with `documento_download_anexo` (or PDF icon); made in the SEI = `documento_interno` icon; blank = `documento_sem_conteudo` icon. Closed old folders load only when opened (`AGUARDE` node).
- (v0.9.0) Creating an external document without screens: GET `documento_escolher_tipo` › POST `frmDocumentoEscolherTipo` (`hdnIdSerie=-1`) › POST `frmDocumentoCadastro` with the type (`trocarSerie()`) › POST with `hdnFlagDocumentoCadastro=2` (`confirmarDados()`). Pages and bodies are ISO-8859-1. The duplicate check (`documento_recebido_duplicado`) is only the page's JavaScript, so it is skipped.
- (v0.8.1) After a successful Salvar of an external document, the SEI redirects the form's frame to the process page (`arvore_visualizar`, with `#divArvoreHtml`); an error returns another page. Source: SEI++ `cs_modules/procedimento_visualizar/dropzone.js`, which also shows how to add a file without the form (open `documento_receber`, upload to `documento_upload_anexo`, POST the form fields).
- (12/11/2026) The IFTO SEI was updated to **SEI 5** (scripts with `?5.0.4-2.45.1`). Features built for the old SEI need to be tested again.
- (v0.1.1) **Password recognized by the browser:** SEI 5 uses MaskedPassword (text field with "●" and the password in a hidden field), and Firefox stopped saving and filling in the password. On the login page (`login.php`) and when signing (`acao=documento_assinar`, including inside the signing window), the extension replaces both with a normal password field, with the same id and name (`pwdSenha`), as in the old SEI. On by default; can be turned off in the settings.
- (v0.22.2) New **internal** document page: `acao=documento_gerar` (existing one: `documento_alterar`). Same access-level fields `#optPublico`/`#optRestrito`/`#optSigiloso` in `frmDocumentoCadastro`; the extension marks Público only when no level is marked (Edital Gabinete came with no level marked), never the format, never Salvar.
- (v0.5.0) **Saved passwords:** Firefox also suggests passwords from other `ifto.edu.br` sites (SUAP, Moodle…). The extension cannot change this; the fix is the Firefox setting `signon.includeOtherSubdomainsInLookup = false` (step by step in `../publicacao.md`, "Saved passwords in the SEI").
- SEI 5 signing window (`acao=documento_assinar`): form `#frmAssinaturas`, job title `#selCargoFuncao` (loaded by AJAX), password `#pwdSenha` (Enter signs), button `#btnAssinar` (`assinarSenha()`). Process bar buttons: images with title "Assinar Documento" and "Ciência" inside `#divArvoreAcoes`.
- SEI++ details (versions, how to build the package, license): `../referencias/seipp.md`.
- (v0.20.0, spec `compras-ifto-no-sei`) Creating an **internal** document without screens: same start as the external one (`documento_escolher_tipo` › POST `frmDocumentoEscolherTipo` with `hdnIdSerie` = the type id read from `escolher(<id>)` on that page) › form `frmDocumentoCadastro` with `rdoTextoInicial` (the "Nenhum" option), `rdoNivelAcesso` (0 Público, 1 Restrito + `selHipoteseLegal`) and `hdnFlagDocumentoCadastro=2`. Not yet confirmed on the IFTO SEI (test T90): the editor link (`editor_montar`) and the text link (`documento_visualizar`) are looked for in the answer and, if missing, in the new document's page in the tree (third argument of `infraArvoreNo`).
- (v0.14.0; v0.17.0 for every external document) **"Nome na Árvore" takes at most 50 letters** (`maxlength="50"` on the SEI 5.0.4 form; the document type, e.g. "Consulta", is not counted). The extension cuts at the last whole word and drops a final dot, comma or dash (`nomeNaArvore` in `comum/sei.js`).

## Tables in the editor (v0.24.0)

- Every unit, every document type; one switch for each part in the settings (`moverTabelas`, `margensTabela`, on by default).
- Cut/copy and paste in the **same editor window**: when the copied part has a table, the paste puts back the editor's own copy (model), not the clipboard HTML, so width, column widths and margins stay. Ctrl+Shift+V, drag and drop, pasting in another window and parts without a table stay with the SEI. Ctrl+Z undoes it.
- SEI 5 keeps the left margin of a table in its own `recuo` setting (only with the table aligned to the left) and the other margins in the HTML styles; saved as `margin:10px auto 10px 28px` like the old SEI. v0.25.1: "Propriedades da tabela" has four fields in px (Acima, Direita, Abaixo, Esquerda) filled with what the editor shows now (Direita: the saved value, else 0); on OK only the changed fields apply; pasting the old `margin:` format in a field fills all four. A 4th button in "Alinhamento" ("Alinhar com o texto") aligns left and fills 10, 0, 10, 28 px (text styles use margin-left .75cm). Button text inside CKEditor buttons only shows with `ck-button_with-text` (why the v0.24.0 button looked blank).

## Long numbers in edital items (v0.25.0)

- "Item nível 2/3/4 Edital" put the number in a fixed box (10, 15, 18 mm); "10.10." does not fit and the text goes to the next line (editor, document, PDF). Swapping to "Item_Nivel2" is not possible everywhere: in Minuta 3384558 the SEI does not allow it in the main section (`permitidoEm`).
- Fix (user's choice, 18/11/2026): a `<style>` block at the start of the first edital item, like SEI Pro's MINUTA mark (the SEI keeps and prints it). It only lets the box grow (`min-width` = old width, `box-sizing:border-box`), so short numbers stay identical. Recognized by the comment `extensao-ifto: numeracao do edital` (the editor drops the `<style>` attributes). "Remover marca MINUTA" does not touch it.
- The box "Corrigir a numeração" appears in every unit and document type only when a paragraph is really broken (first letter below the first line), checked again 1.5 s after each change; nothing changes without the click; never saves.

## MINUTA mark in editais (v0.22.0)

- The "MINUTA" in the background is not a paragraph: SEI Pro puts a `<style>` block in the text (`data-style="seipro-watermark"`, `content: "MINUTA"`) plus a label `span.minutaAncora` "* MINUTA DE DOCUMENTO" (one pair per marked paragraph). Creating the Edital from the minuta copies them. In SEI 5, deleting the label is not enough: the style block stays hidden in the paragraph and keeps printing MINUTA (v2 of Edital 3390039, 18/11/2026), and editing the HTML by hand is not saved.
- In the editor window (`acao=editor_montar`), only for type **Edital** (window title "SEI/IFTO - número - Edital …"; "Minuta de Edital" keeps the mark), a box "Remover marca MINUTA" appears when the mark is in the text. It removes every style block that writes MINUTA and every label, also recognized by the text "* MINUTA DE DOCUMENTO" (v0.22.1: the SEI 5 editor gives the text without the `minutaAncora` class); a paragraph left empty is removed. Other styles and the visible word "minuta" (e.g. title "minuta de EDITAL") stay; a warning lists where it is, for the person to fix by hand.
- The extension never saves here: the person checks and clicks Salvar (closing without saving undoes it; Ctrl+Z also works in SEI 5).
- Setting "minutaEdital": Automática = only in the Direção-geral (PAL/REI/IFTO), Sempre ligada, Desligada. The editor window does not show the unit: it comes from `infra_unidade_atual` in the address (number → name saved by every SEI page) or from the SEI window that opened the editor.
