# IFTO SEI: creating and including documents

- (v0.6.0) External document page: new = `acao=documento_receber`, existing (with or without file) = `acao=documento_alterar_recebido`. Fields: `#selSerie` (type, `onchange=trocarSerie()`), `#txtDataElaboracao`, `#optNato`/`#optDigitalizado`, `#optPublico`/`#optRestrito`/`#optSigiloso`, Salvar `#btnSalvar` (`confirmarDados()`, which first asks the SEI about a duplicate: same type, date and number). Gerar Documento page: "Externo" is `a[onclick="escolher(-1)"]`.
- (v0.9.0) Creating an external document without screens: GET `documento_escolher_tipo` › POST `frmDocumentoEscolherTipo` (`hdnIdSerie=-1`) › POST `frmDocumentoCadastro` with the type (`trocarSerie()`) › POST with `hdnFlagDocumentoCadastro=2` (`confirmarDados()`). Pages and bodies are ISO-8859-1. The duplicate check (`documento_recebido_duplicado`) is only the page's JavaScript, so it is skipped.
- (v0.8.1) After a successful Salvar of an external document, the SEI redirects the form's frame to the process page (`arvore_visualizar`, with `#divArvoreHtml`); an error returns another page. Source: SEI++ `cs_modules/procedimento_visualizar/dropzone.js`, which also shows how to add a file without the form (open `documento_receber`, upload to `documento_upload_anexo`, POST the form fields).
- (v0.29.0–v0.29.2, spec `todos-os-estilos`) **All text styles in every document:** the SEI 5 editor's styles live in the `EstiloEditing` plugin (`estilos`: `{ nome, classeCss, permitidoEm: [root names] }`; the class in the text = the style name; config `infra.estilo` = `itens`, `css`, `estiloPadrao`); the dropdown reads `getEstilosPermitidos(root)` on each selection change, so styles added at run time show up. Unknown classes are **dropped** by the editor on opening (its HTML support allows `p` styles and `align`, not classes; seen in T181, 19/11/2026), so the extension reads the original text the SEI gave the editor (`editor.config.get('initialData')`) and puts the style back on each paragraph with the same text, in order (v0.29.3). Putting it back is not the person's edit: if the editor had nothing to save before, the extension calls `resetDirty()` on the editor's `Salvar` plugin (it counts every model change in `documentVersion`), so the SEI does not ask to save a document just opened (v0.31.1, T188). The list also shows bold styles in bold. The list buttons carry the style class, but the editor's CSS hides the background; the extension adds a stronger rule for styles with a background (grey titles). Rules (`comum/todos-os-estilos.js`): list = the 41 Edital styles (document 3384558) + styles learned from every editor opened (`estilosAprendidos`, same name: learned wins); extras only in the roots that accept `Texto_Justificado` or `IFTO_padrao_Alin_Justificado` (else the main section), never header, signature or footer; the type's own first, then extras alphabetical with "★ " (only the shown label changes), a name the type has is not repeated, note at the end; used extras get one hidden `<style>` block (comment `extensao-ifto: estilos extras: names`), updated when they change, removed when none (other blocks untouched). Switch `todosOsEstilos` (Documentos do SEI, on by default, all units); off + document with the block: editor box with "Ligar de novo". Never saves.
- (v0.20.0, spec `compras-ifto-no-sei`) Creating an **internal** document without screens: same start as the external one (`documento_escolher_tipo` › POST `frmDocumentoEscolherTipo` with `hdnIdSerie` = the type id read from `escolher(<id>)` on that page) › form `frmDocumentoCadastro` with `rdoTextoInicial` (the "Nenhum" option), `rdoNivelAcesso` (0 Público, 1 Restrito + `selHipoteseLegal`) and `hdnFlagDocumentoCadastro=2`. Not yet confirmed on the IFTO SEI (test T90): the editor link (`editor_montar`) and the text link (`documento_visualizar`) are looked for in the answer and, if missing, in the new document's page in the tree (third argument of `infraArvoreNo`).
- (v0.27.0, base-e-sei stage 2) **Chosen file on the external document page:** the field `#filArquivo` (form `frmAnexos`) uploads at once (`onchange="objUpload.executar()"`); the SEI's `validar` refuses names with `&#` and files above `10 * 1024 * 1024` bytes (10 MiB, D10: "Arquivo excede o tamanho máximo geral permitido para documentos externos de 10Mb."); allowed extensions: 7z, bz2, cdr, csv, gz, html, json, mp3, mp4, mpeg, mpg, odp, ods, odt, ogg, ogv, pdf, svg, tar, tgz, txt, xls, xlsx, xml, zip (10 MB each). The extension listens to `change` in the capture phase (before the SEI): above the limit it stops the upload and shows the tips; `#` → `_` (D9) by swapping the file in the field (`DataTransfer`); type (D14) and "Nome na Árvore" (D7) from the file name, only when empty (v0.29.3, T170: a type name glued to the next word by a capital letter counts, e.g. "ConsultaOptantes_…" → Consulta; the type list is read from the SEI page itself, 273 types in the saved page). Changing `#selSerie` runs `trocarSerie()`, which **reloads** the form (the chosen file would be lost), so the extension sets `selSerie` and `hdnIdSerie` directly, like SEI++ does when saving. "Hipótese Legal" (`#selHipoteseLegal`) is filled by AJAX only after Restrito is marked; tipo de conferência `#selTipoConferencia` (Documento Original, Cópia Autenticada Administrativamente, Cópia Autenticada por Cartório, Cópia Simples) shows only with Digitalizado. Sigiloso is disabled at IFTO.
- (v0.32.0, user 19/11/2026) **File dropped on a blank external document:** the drop area is the document opened on the right (`ifrConteudoVisualizacao` and the frames inside it). It accepts only when the tree says the open document (`id_documento`) has no file (`documento_sem_conteudo` icon) and has "Alterar Documento Externo" (`externoEmBranco`); any other document keeps the browser's normal behaviour. One file only (several: message pointing to the tree). Confirm window with name, size and warnings (10 MiB, `#`); after "Anexar" the file is uploaded and the Alterar form is saved with everything else as it is (type, date, format, access, tree name), the same code as the SICAF blank documents (`seiPedidos.anexarAoExterno` › `alterarExterno`). Same setting as the tree drag (`arrastarArquivos`).
- (v0.36.1, user 25/11/2026) **After including external documents** (dragged files, SICAF): the window closes, a message disappears by itself after 6 s (errors and Parar keep the window) and the first document in the tree opens (`abrirIncluido`: tree link with `id_documento` from the Salvar answer; else new tree, first id above the old ones). **Type by name:** case, accents, symbols and accents broken by Windows do not matter (`fimDoComeco`); a name that fits several types ("portaria_") chooses nothing: the rules and default type come first, else those types are shown first. **Drop area:** disappears 0.9 s after the last `dragover`, has "× Fechar", and is off while a SEI document form is open on the right.
- (v0.27.1, base-e-sei stage 3) **Files dragged onto the process tree:** the drop area is the tree frame (`ifrArvore`). The extension reads the type list of the Externo form (same start as v0.9.0, read only), shows the check list (type: file name › user rules › default type, else the person picks; tree name; date: today, or the file's date with `arrastarDataDoArquivo`, D6; size: above 10 MiB or `#` with the rename off = not sent) and sends only after "Incluir no processo", one document at a time, with the same code as the SICAF (`seiPedidos.incluirNaJanela` › `incluirExternos`: upload to `documento_upload_anexo`, then Salvar). Always Nato-digital and Público (provisional D15). Every SEI request has a time limit (2 min; file upload 5 min) and the window has Parar/Cancelar.
- (v0.37.0, user 26/11/2026) **Abbreviations at the start of the file name** (chosen file and dragged files, `comum/documento-externo.js` `SIGLAS`): NF, DANFE, NFe, NF-e, NFC-e, NFCe, NFSe, NFS, NFS-e → "Nota fiscal" (tree name = the rest, like a type name); RANFS → "Documento" (tree name = the whole name, "Documento" alone says nothing). Checked after the SEI type names (longest wins) and before the person's own rules; same end-of-word rule as the types ("NFe1" is not "NF"); type missing from the SEI list: nothing chosen.
- (v0.14.0; v0.17.0 for every external document) **"Nome na Árvore" takes at most 50 letters** (`maxlength="50"` on the SEI 5.0.4 form; the document type, e.g. "Consulta", is not counted). The extension cuts at the last whole word and drops a final dot, comma or dash (`nomeNaArvore` in `comum/sei.js`).
