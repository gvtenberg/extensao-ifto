# Automatic SICAF (invoices for payment)

**Sections**: Goal and limits · Settings and units · Pending invoices · Invoice × ateste check · SICAF search · Adding to the SEI · Selected CNPJ

Decided on 13/11/2026 (spec `specs/feitas/sicaf-automatico.md`, v0.10.0 to v0.15.0). Code map in `arquitetura.md`.

## Goal and limits

- For every invoice: find those still without SICAF or Simples Nacional, get the "Situação do Fornecedor" PDF from the SICAF and the Simples Nacional lookup PDF (site and PDF rules in `specs/feitas/consulta-simples.md`, section 4) and, after one confirmation, add Sicaf and Consulta (each with its PDF) per supplier and one blank Anexo per invoice. **One button for everything** (v0.18.0, user 13/11/2026): the old "Incluir Sicaf, Consulta e Anexo" (blank documents) button and its setting were removed.
- The gov.br login (SerproID QR code, 6-digit code) is personal: **never automated**. The extension opens the Compras login page and clicks "Entrar com Gov.br" in the "Governo" card once per search (v0.17.3, user request). v0.21.2 (user 18/11/2026): only when it did that click, on the Gov.br login page (`sso.acesso.gov.br/login`) it clicks "SerproID" (`#login-external-authentication-neoid`, inside "Seu certificado digital em nuvem") once per search; the Gov.br hCaptcha, QR code and code stay with the user. Going straight to the Serpro page is impossible (one-time `authorization_id` + hCaptcha on Gov.br). If the session is still active, Gov.br does not open and nothing is done. v0.21.3 (user 18/11/2026): this click is an option, **off by default** (`entrarComSerproId`); access to `sso.acesso.gov.br` is a separate optional permission (`ORIGENS_GOVBR`), asked when the box is ticked and removed when unticked (refused = box stays off). The settings card explains what is accessed, what is not, and what is gained or lost.
- Filling the Anexo (Contratos billing document) and the TCU lookup are later ideas (`melhorias-futuras.md`).

## Settings and units

- Option "SICAF e Simples Nacional" (D4): **Automática** (default) = the invoice button only in the CGOC (CGOC/GAC/DAP/PAL/REI/IFTO); **Sempre ligada** (bidding team, until it has its own settings; v0.18.0) = only the "Incluir SICAF" bar button (type or paste the CNPJ, no invoice needed) in any unit with a process open, which adds **only the Sicaf** (also in the CGOC; no invoice notice); **Desligada** = nothing. With Automática, the selected-CNPJ buttons and menu also work only in the CGOC (v0.16.0; elsewhere the menu says to choose "Sempre ligada").
- Selected CNPJ (v0.18.0): in the CGOC one button "Incluir SICAF, Simples e Anexo" (Sicaf, Consulta and the Anexos of that supplier's pending invoices); elsewhere (and in the CGOC with "Sempre ligada") only "Incluir SICAF" (v0.26.10, user 19/11/2026: other units check the company's SICAF in bidding processes, before any invoice; only the CGOC uses invoice data and the Simples). Right-click menu: everything in the CGOC with Automática, only the Sicaf otherwise.
- Waits (v0.26.10, T94): after the search reloads the page, the SICAF waits up to 15 s for the result line (or a SICAF error) and the Simples up to 8 s before saying the CNPJ was not found or refused; on the Área de Trabalho, the page itself waits until the login finishes (the name button `#avatar-dropdown-trigger` appears, up to 15 s) and then uses the user menu (v0.37.0; v0.29.3 to v0.37.0 first tried the SICAF start page address, which never worked). During a search, an Área de Trabalho in any tab counts, also when it changes address without reloading (user, 19/11/2026); without a search, nothing happens there.
- Invoices window (v0.26.10, T76): compact cards, about 10 invoices fit without scrolling (scroll kept as a last resort); a click on a free part of an invoice card ticks or unticks it. v0.29.3 (T160, T173): the checkbox is always shown (also with one invoice) and the hint says to untick the invoice that should not be searched; title "Nota N – fornecedor" (SEI number in the "Ver a nota" tip); CNPJ on one line ("CNPJ:" + options + field); warnings "Não consegui ler a nota: confira o CNPJ." / "A nota é uma imagem: confira o CNPJ."
- Access to Compras.gov.br (`www3.comprasnet.gov.br`, `comprasnet.gov.br`, `www.comprasnet.gov.br`, `cnetmobile.estaleiro.serpro.gov.br`) and to Downloads is an **optional permission**, asked once from the settings ("Permitir acesso ao Compras.gov.br"), so colleagues who do not use it are never asked.

## Pending invoices

- D10: by position in the tree: everything **after the last "Folha de Encaminhamento"** (or everything, if there is none) still needs documents.
- Tree names: invoice = external PDF "Nota fiscal nº <n> <supplier>" (v0.37.0, user 26/11/2026: "Fatura …" too; its blank Anexo is "Instrumento de Cobrança Fatura nº …"); ateste = SEI document starting with "Ateste"; one ateste may cover several invoices of the same supplier.
- Ateste lines read: "Empresa:", "CNPJ:", "Número da nota fiscal: 3.626 ( 3384844 )" (SEI number when given), "Nota de Empenho:" / "Número do empenho:", "Valor da nota fiscal:".
- Supplier already done: a Sicaf **with a file** after the last Folha whose PDF contains that CNPJ (names differ between invoice and SICAF, so the CNPJ decides), and a Consulta **with a file** whose PDF has a CNPJ with the same first 8 digits (the Simples covers the whole company, head office and branches; v0.18.0). An invoice is pending while its supplier lacks either; each search only asks for what is missing. Invoice Anexo done: an Anexo with a file after the last Folha with its number. Blank documents do not count. (v0.18.2) The invoice's CNPJ is the ateste's **or** the issuer read on the invoice PDF (the one the search uses). This check also runs for the selected CNPJ (before opening the sites) and again right before including, with the current tree: a Sicaf/Consulta already there for that CNPJ is never added again; one that cannot be opened gets a yellow warning. Failed reads are not remembered.
- (v0.18.5, user 18/11/2026) Two or more invoices in the window: each card has "Consultar esta nota", all checked; an unchecked invoice (e.g. cancelled: the PDF alone does not show it) gets nothing (no Sicaf, Consulta or Anexo) and skips the ateste checks. The choice is not remembered (the bar button keeps counting it).
- D2: button "N notas sem SICAF ou Simples – Buscar" (v0.37.0: counts companies, one search each: "1 empresa sem SICAF ou Simples (2 notas) – Buscar"); the notes window button too: "Buscar SICAF e Simples de 1 empresa (2 notas)". SICAF and Simples are per company (CNPJ), the Instrumento de Cobrança Anexo per invoice in the extension bar; nothing opens before the click. No pending invoice: no button.

## Invoice × ateste check

- D1/D8: the **invoice PDF is the reference** (ateste and Folha are typed by hand). Supplier CNPJ = first formatted CNPJ with valid check digits that is not IFTO's (10.742.006/…); the issuer comes first, a carrier may come later.
- Checked: buyer is Campus Palmas **10.742.006/0003-50** (another 10.742.006/… = another IFTO unit); ateste × invoice: CNPJ, invoice number, value (R$), empenho (only when the invoice mentions one) and company name. Comparison ignores dots, leading zeros, accents and case; names accept abbreviations ("SERV." = "SERVIÇOS").
- D9: different CNPJ, number, value or empenho, another IFTO unit or no Campus Palmas CNPJ → **red**, needs a second click "Continuar mesmo assim"; company name difference → **yellow** notice only.
- Scanned invoice (no text) or different CNPJs: the user picks (invoice or ateste CNPJ) or types the CNPJ.

## SICAF search

- The extension opens the SICAF "Situação do Fornecedor" page in a new tab. If the SICAF refuses (acesso negado / sessão expirada), it opens the Compras login page once (and clicks "Entrar com Gov.br"); after the login, on the Área de Trabalho, it always opens the SICAF through the user menu (`#avatar-dropdown-trigger` › "SICAF"), never by its address (v0.37.0, T299: the menu asks the Compras for a SICAF address with a one-time pass and opens it with `window.open(…, '_blank')`; without the pass the SICAF hangs or says "Sessão expirada"). The page's new window is turned into the same tab (the browser blocks a window not opened by the person). Each step is logged in the console ("[extensão IFTO] Área de Trabalho: …"); after 20 s without the SICAF the notice says where to click. If the SICAF opens in another tab, the notice on the old tab is removed. When the search ends (success or not), the search tab is closed (v0.21.6). If the SICAF still refuses, it goes to the Área de Trabalho at most twice more, then a notice says where to click. Any SICAF page that opens continues the search.
- The SEI window does not block the page (v0.17.3): the user can click the tree and see the note while it is open.
- For each CNPJ: Pessoa Jurídica, CNPJ, Pesquisar, "Situação do Fornecedor"; the PDF the SICAF sends is caught and checked (CNPJ inside the PDF must be the same; otherwise red).
- D5 (changed 13/11/2026, v0.18.2, user): every click fetches the SICAF and Simples PDFs again from the sites; **nothing is kept by the extension** (PDFs live only inside the running search and are erased at the end; old day memory `sicafPdfs`/`simplesPdfs` is deleted on start). The PDF goes into the SEI; a copy in Downloads (`consultarSituacaoFornecedor_<CNPJ>_<yyyy-mm-dd>.pdf`) only with the setting on: "copiaSicaf" and "copiaConsulta" (both on by default). The supplier name shown comes from the SICAF PDF (razão social).
- **Site down or slow** (v0.18.5, user 18/11/2026; general rule "External systems can be down"): the SEI window checks the search every 3 s and shows the site and CNPJ in progress. After 45 s without any step (`SEM_RESPOSTA_MS`), a yellow warning says the site may be down (or the Gov.br login is pending); it never cancels by itself. Always available: "Pular o SICAF" / "Pular o Simples Nacional" (what was missing from that site is "Não consultado" and not included; goes on to the next site or the final window) and "Cancelar e voltar" (closes the site tab, back to the invoices or CNPJ window with the choices kept). A site tab closed by the user ends the search with what came. When any CNPJ ended without a PDF, the extension closes the site tab it opened. The final window has "Voltar" too.
- v0.36.2 (user, 25/11/2026): before the search, one plain request per site (no login, 10 s limit) checks if SICAF and Simples answer; any answer below error 500 counts. If one does not: "Cancelar", "Pular" (that site is not opened; each CNPJ keeps the reason) or "Tentar assim mesmo".
- v0.37.0 (T271, T274, T260, 26/11/2026): the CNPJ fields of the extension's windows put the mask (dots, slash, hyphen) while the person types and check the two last digits before any search. On the SICAF page the extension waits for the site's own mask, writes the number and checks it is in the field; otherwise it stops with a clear message (before: empty field, "Campo CNPJ inválido", then a false "não encontrou"). After the result line appears it waits 2.5 s before "Situação do Fornecedor"; with the SICAF notice "falha do sistema" it tries twice more (6 s, 12 s). On the Área de Trabalho, the SICAF item of the user menu opens in the same tab (the browser blocked the new window opened by the extension, which is why the SICAF did not open); in Firefox a new window asked by the page also becomes the same tab. Automatic steps never bring a browser window to the front (two monitors: the focus stayed where the person was typing); the Compras editor window opens without the focus.

## Adding to the SEI

- One confirmation window lists each supplier, CNPJ, the PDF obtained and the documents to create; nothing is written to the SEI before the click (`CLAUDE.md`, Conventions). Red warnings need a second click.
- Order: per supplier Sicaf (PDF, "Nome na Árvore" = SICAF company name without the final dot, D3) and Consulta (Simples PDF, "Consulta Simples Nacional <Nome Empresarial>"; not created when the lookup failed, so the invoice stays pending); per invoice one blank Anexo "Instrumento de Cobrança NF nº <number without leading zeros> <supplier as in the invoice tree name>" (D7). Example: CHC invoices 63 and 64 → Sicaf, Consulta, Anexo 63, Anexo 64.
- **Blank documents are reused** (decided 13/11/2026, v0.16.0): blank Sicaf, Consulta and Anexo after the last Folha that still have no tree name ("Sicaf (3385629)") are filled through "Alterar Documento Externo", in tree order: Sicaf and Consulta get the PDF and name, Anexo the name. Only the missing ones are created.
- **Order kept with documents without PDF** (v0.18.6, user 18/11/2026; spec `specs/feitas/sicaf-em-branco.md`): CGOC order is Sicaf → Consulta → Anexo → Folha and SEI 5.0.4 cannot reorder. A skipped or failed site gives a Sicaf/Consulta **without PDF but with the full name** only when a later document of that company goes in the same click (SICAF skipped + Simples OK → Sicaf without PDF, Consulta, Anexos; Simples skipped → Sicaf, Consulta without PDF, Anexos; also when the Consulta is already in the process). Both skipped or failed (and none in the process) → nothing for that company, not even the Anexo. One without PDF already there takes its place (no second one).
- Later, a named Sicaf/Consulta without PDF leaves the invoice pending; the next search puts the PDF and the official name **into that same document**. Company: the CNPJ in the PDF of the neighbour (Consulta right after the Sicaf, Sicaf right before the Consulta), else the name. Created by another unit (no "Alterar"): red warning and nothing for that company. One before the last Folha: red bar notice "Sicaf sem PDF: <empresa>" (warning only; PDF attached by hand).
- Same fields as the old one-click payment documents (`specs/feitas/documentos-pagamento.md`): today's date, Nato-digital, Público. "Nome na Árvore" takes at most **50 letters**: cut at the last whole word (rule for every external document in `sei.md`).
- v0.37.0 (T259): a dragged file named `consultarSituacaoFornecedor_<CNPJ>_<date>.pdf` (the SICAF PDF) gets the type Sicaf and the CNPJ with mask as "Nome na Árvore".

## Selected CNPJ

- D6: selecting only a CNPJ (14 digits, with or without dots; check digits valid) on an SEI page shows buttons next to it (v0.18.0: see Settings and units); in the browser PDF viewer (where extensions cannot act on the page) the right-click menu "Buscar SICAF deste CNPJ"; fallback: type or paste in the window. It acts right away on that CNPJ (no list), only where the option is on (see Settings and units): CGOC adds Sicaf, Consulta and the Anexos of that supplier's pending invoices; other units only the Sicaf or only the Consulta (button chosen).
